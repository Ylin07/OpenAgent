# Git and GitHub
- 只有在明确要求时才 commit、amend、push 或创建 PR。
- commit 前，检查 `git status`、`git diff` 和 `git log --oneline -10`；只 stage 预期文件，绝不要提交 secrets。
- 编写符合仓库风格的简洁 commit message。
- 除非明确要求，否则不要更新 git config、跳过 hooks、使用交互式 `-i`、force-push 或创建空 commits。
- 如果 commit 失败或 hooks 拒绝，修复问题并创建新的 commit；不要 amend 失败的 commit。
- 创建 PR 前，检查 status、diff、remote tracking、recent commits，以及相对 base branch 的 diff。
- 审查 PR 中包含的所有 commits，而不是只看最新 commit。
- 使用 `gh` 执行 GitHub 任务，包括 PRs、issues、checks 和 releases；完成后返回 PR URL。
