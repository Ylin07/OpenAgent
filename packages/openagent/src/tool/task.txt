启动一个新 agent，自主处理复杂的多步骤任务。

使用 Task 工具时，必须指定 subagent_type 参数来选择要使用的 agent 类型。

不要使用 Task 工具的情况：
- 如果要读取具体文件路径，使用 Read 或 Glob 工具而不是 Task 工具，以便更快找到匹配项
- 如果要搜索类似 "class Foo" 的具体 class definition，使用 Grep 工具而不是 Task 工具，以便更快找到匹配项
- 如果要在某个具体文件或 2-3 个文件中搜索代码，使用 Read 工具而不是 Task 工具，以便更快找到匹配项
- 如果没有可用 agent 适合该任务，直接使用其他工具


用法说明：
1. 尽可能并发启动多个 agents，以最大化性能；做法是在单条消息中使用多个工具调用
2. 一旦将工作委派给某个 agent，就不要自己重复这项工作。继续处理不重叠的任务，或等待结果。对于后台任务，结果准备好后你会自动收到通知。
3. agent 完成后，会向你返回一条消息。agent 返回的结果对用户不可见。要向用户展示结果，你应向用户发送文本消息，简洁总结该结果。输出中包含 task_id，之后可复用它继续同一个 subagent session。
4. 除非提供 task_id 来恢复同一个 subagent session（它会继续之前的消息和工具输出），否则每次 agent 调用都会以全新上下文开始。全新开始时，你的 prompt 应包含高度详细的任务描述，让 agent 自主执行，并且明确说明 agent 在最终且唯一返回给你的消息中应返回哪些信息。
5. 通常应信任 agent 输出
6. 清楚告知 agent 你期望它写代码，还是只做研究（搜索、文件读取、web fetches 等），因为它不知道用户意图。如果可能，告诉它如何验证工作（例如相关测试命令）。
7. 如果 agent description 提到它应被主动使用，应尽力在无需用户另行要求的情况下使用它。自行判断。
